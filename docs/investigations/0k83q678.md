# Investigation — test-baseline-grep-under-set-e (`0k83q678`)

## Symptoms

`.claude/skills/yolo-afk-dev/scripts/test-baseline.sh` (and its sibling
`test-current.sh`) exit non-zero without writing their output JSON exactly
when the test run has **zero failures** — the success case. Downstream, the
yolo baseline/diff flow sees a missing `test-baseline.json` /
`test-current.json` and treats a green test run as an orchestration error.

## Repro status

Reproduced deterministically (see `tests/scaffolding/yolo-test-scripts.test.ts`):

- `test-baseline.sh <state> <prd> HEAD "true"` — test cmd produces no
  failure-marker lines → script exits 1, no `test-baseline.json`.
- `test-current.sh <state> <prd> <issue> <worktree> "true"` — same shape:
  exits 1 at the failure-extraction line, no `test-current.json`. (On hosts
  without `timeout(1)` the inner test cmd exits 127 first, but that is
  caught by the intended `set +e` window; the death still happens at the
  grep line. `timeout` portability is a separate item, `y7vzx3be`.)

## Hypotheses tested

1. **grep's no-match exit under `set -e` kills the script** — CONFIRMED.
   Both scripts run `set -euo pipefail` (line 18/13). The test command
   itself is correctly wrapped in a `set +e … set -e` window, but the
   *failure extraction* afterwards is not:
   - `test-baseline.sh:66` — `FAILURES=$(grep -E '…' "$RAW" | sed | awk | sed)`
   - `test-current.sh:48` — `CURRENT_FAILURES=$(grep -E '…' "$RAW" | sort -u)`

   `grep` exits 1 on zero matches. With `pipefail`, the pipeline's exit is
   1; a failing command substitution in an assignment propagates under
   `set -e`; the script dies before writing its JSON. With any real test
   failure present, grep matches, exits 0, and the script completes — the
   bug fires only on green runs.

2. **`2>/dev/null` masks it** — rejected: stderr redirection does not touch
   the exit code.

## Root cause

`grep` treats "no matches" as exit 1; both scripts run their
failure-extraction pipelines under `set -euo pipefail` outside the
deliberate `set +e` window, so a fully passing test run (no failure
markers to match) aborts the script before the output JSON is written.

## Fix

Guard the grep in both pipelines so no-match is not an error:
`{ grep -E '…' "$RAW" 2>/dev/null || true; }` — stdout is unchanged
(empty on no match), the JSON's `failures`/`current_failures` arrays
render empty, and real errors elsewhere in the pipeline still fail fast.
