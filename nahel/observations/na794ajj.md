Standing human product constraint (Jim, transcribed repeatedly during the Decision Digest charting): a read command should start with LESS information and let the user or an LLM query, filter, or zoom for more, rather than flooding the first response. It decided several Decision Digest questions at once — the unfiltered default retains only the newest 10, filters are the intended path to depth, provenance problems show as a compact additive [incomplete] badge instead of inline diagnostics, and v1 ships stable compact human-readable text with no JSON. Treat it as the default posture for any new nahel read surface, not a decision-digest-local rule.
