Every command that takes an item reference accepts the item's slug as well as its id, the way the roadmap layer already accepts a node slug or id (resolveNodeRef, src/commands/roadmap-ref.ts): item update, run start, progress --item, observe --item, log --data item=, claim, and their siblings. A slug that names exactly one item resolves; a slug naming several REFUSES and lists the candidates with their ids so the caller picks — item names are not unique per store and are not being made unique (the store already holds two items named decision-digest, and natural names like fix-tests will collide across unrelated epics forever). Slugs are input sugar only: stored records, journal payloads and cross-references keep carrying ids alone, so merge-safety across parallel worktrees is untouched. This requires an amendment to CONTEXT.md, which today states that references always use the id and never the slug — human sign-off, product governance. Motivation: a bare id is unreadable to a human bouncing between agents and projects, and it is equally opaque in a commit message, a PR title, or a handoff to another agent. Pair the ref change with the display convention that every command echoing an item names it as slug (id).
